# W4 · Lahari — beat-OSRM headline, ablations, and the first agent-eval number

Week 4 in full: Random Forest and GBT (MLlib), tuned by k-fold CV and ranked on MAE
(D-024), against the corridor-mean baseline Week 3 fixed as the number actually worth
clearing (D1-D2, §1-4); feature-block ablations at the tuned hyperparameters (D3-D4,
§6, D-027); and the document-extraction evaluation harness scoring Krishna's agent
(D5, doc-eval section below, D-028) — three scripts owning three sections of one
document per GIT_RULES §2.

Regenerate rather than editing numbers by hand:

```bash
python -m src.ml.models                # D1-D2: train, evaluate, write up
python -m src.ml.models --ablations    # D3-D4: price the two feature blocks
python -m src.ml.doc_eval              # D5: score Krishna's predictions
```

`src.ml.models` reads `data/processed/features_v1` (Stage 4, Mounika) and writes
`benchmarks/raw/w4_model_metrics.csv`, `w4_classifier_metrics.csv`,
`w4_corridor_gains.csv`, `w4_feature_importances.csv`, `w4_cv_report.json`,
`w4_model_report.json`, the two fitted MLlib pipelines under `data/models/` that
Mounika's auto-retrain script (`src.automation.retrain`) reads, and (with
`--ablations`) `w4_ablations.csv`. `src.ml.doc_eval` reads Krishna's predictions
files (`week4-krishna-doc-agent`) and writes `w4_doc_eval_field_accuracy.csv`,
`w4_doc_eval_summary.json`, and `benchmarks/agent_evaluation.md`.
