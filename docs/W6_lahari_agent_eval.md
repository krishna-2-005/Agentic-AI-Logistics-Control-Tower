## Results freeze (D1-D2)

**31 Layer 1 numbers, each recorded with the file it came from and a hash of that
file's contents**, in `benchmarks/results_freeze_v1.json`, and written up for a reader
in [`RESULTS_SUMMARY.md`](RESULTS_SUMMARY.md). `--verify` recomputes all 31 and says what
moved. Current state: **clean, 0 changed, 0 unreadable**.

The freeze does not make anything immutable, and saying so matters. Re-running a stage
overwrites its artefact exactly as before. What the freeze adds is **detection**, because
the risk to a paper is not someone editing a number — it is a stage being re-run,
an artefact moving by 0.2, and the prose continuing to say what it always said (D-046).

Two lists, kept separate on purpose: `changed` (a value moved) and `files_rewritten` (the
bytes moved, the numbers did not). A check that cried wolf every time a table was
regenerated would be a check people learn to ignore.

An entry whose source file is missing is reported as a **problem**, not skipped. A Layer 1
number that can no longer be traced to a file is a finding.

## What the Exception Agent evaluation says

**The headline is not the headline.** 72.1% notification precision is *the stream's*
precision, not the agent's: the agent notifies on every alert it is handed, so as an
alerting system it inherits whatever the streaming job flagged. D-040 already showed that
flag is the weakest real classifier in the project.

**The useful result is that its severity grades work.** Precision climbs monotonically
from 53.2% at `low` to 91.8% at `critical`, and the policy table prices the trade: notify
at `high` or above and you send 42% of the volume at 88.6% precision, still reaching 46.6%
of every delayed leg in the replay. A severity floor is a real lever, and Week 7 should
pull it (D-047).

That is a result the arithmetic severity rule made possible. A model-assigned grade could
not have been evaluated this way at all, because re-running it would produce different
grades and there would be nothing stable to score.

**One number in the generated table needs a caveat.** Event-to-alert reads 60.3 s median
here because this replay landed in a single large micro-batch; latency is one batch time,
and the batch held 4,000 events. The properly measured figure is Mounika's D5 harness at
**28.9 s** median with the batch size controlled. The agent's own contribution is 0.04 ms,
which is the only part of that number this evaluation is really about.

**What it does not measure.** Recall against *all* delayed legs (89.7%) is a property of
the stream plus the agent, not of the agent alone — the agent cannot notify about a
leg nobody flagged. And a notification's *usefulness* is untested: precision says the
shipment really was late, not that telling someone helped.

## What the Invoice Auditor evaluation says

**86.7% accuracy, zero false disputes, 8 misses — and all 8 are the same kind.**

The set is mine, not Krishna's: a different seed, and ten kinds against his five. Three
sit deliberately at the auditor's edges, because a set of easy cases returns a number
that means nothing:

- `other_at_edge` — other charges at exactly the 18% ceiling. Correct answer:
  approve. **2 of 2.** A checker testing `>` where it means `>=` fails here and nowhere
  else.
- `rounding_total` — a total off by four tenths of a paisa. Correct: approve.
  **9 of 9.**
- `overcharge_hidden` — freight 10% above the corpus's own band, which is *inside*
  the auditor's 15% tolerance. Correct: dispute. **0 of 8.**

**That last one was designed to fail, and it is the most valuable case in the set.** A
seeded set the auditor passes completely tells you the cases were easy. This one puts a
number on the tolerance: a supplier can overcharge by up to 15% and be approved. The
tolerance stays for v1 — zero false disputes is the right direction to be wrong in
— but the blindness now has a price tag instead of being an unstated assumption
(D-047).

**Every other kind is 10 of 10 or better, and no clean invoice was disputed.**

## Tests

`tests/test_agent_eval.py` — 22 tests across all three deliverables: that `--verify`
notices a value that moved *and* one that vanished, that a missing source is reported
rather than skipped, that recall is measured against every delayed leg rather than only

does slip past the auditor, so the published miss is a property of the code and not of my
description of it.

## What is not in this section

- **Neither evaluation measures the language.** Both agents' wording is drafted by a
  model and neither draft was scored: today's quota went to Week 5's order evaluation, so
  every run here used the template fallback. Prompt quality is Week 7's problem.
- **The Exception Agent's recall is bounded by the stream.** It cannot notify about a leg
  nobody flagged, so 89.7% is a statement about the pair, not the agent.
- **The invoice rate band is still circular** (D-043): the auditor and the corpus share a
  rate model, so this measures consistency with the network's own observed rates, not
  correctness of those rates.
- **The freeze covers Layer 1 only.** Week 7's RAG and scale numbers are not in it yet,
  and adding a reported number to the paper means adding a line to `ENTRIES` — a
  number that is not there is not frozen.

**Decisions:** D-046, D-047.
