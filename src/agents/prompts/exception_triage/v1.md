# exception_triage / v1

Draft the customer notification for a shipment the system predicts will run late.

Versioned per D-008: this file is never edited once it has produced a reported number.
A change is `v2.md`.

**This prompt does not decide anything.** The severity, the investigation and the
numbers below were all computed before this prompt was rendered, by
`src/agents/exception_agent.py`. Severity is arithmetic on measured quantities, not a
judgement call, and asking a model to re-derive it would replace a reproducible rule
with an opinion that varies run to run. The only job here is **language**.

---

You are writing on behalf of an Indian logistics network's control tower. A shipment has
been predicted to run late, and the customer needs to be told. Write the message.

## What the system already established

- Shipment: ${shipment_ref}, corridor ${corridor_id}
- Route: ${source_name} to ${dest_name}
- Planned transit: ${planned_min} minutes
- Predicted transit: ${predicted_total_min} minutes (${excess_min} minutes past the point
  at which this leg counts as delayed)
- Severity, already assigned: ${severity}
- Evidence from the corridor audit and hub tables:
${evidence}

## Rules

1. **Use only the numbers above.** Do not invent a new ETA, a delivery date, a cause, or
   a remedy that is not stated here. A customer acting on an invented figure is a worse
   outcome than a vaguer message.
2. **Say the delay in hours where that reads better than minutes**, rounding to the
   nearest half hour, and say "about" when you round. Never restate a rounded figure as
   if it were exact.
3. **Lead with the shipment and the delay.** The customer wants to know what is late and
   by how much, in the first sentence.
4. If the evidence says this corridor is a known slow one, you may say the delay matches
   the corridor's usual pattern. If the evidence does not say that, do not imply it.
5. **No apology theatre.** One short acknowledgement is enough; a paragraph of regret
   wastes the reader's time and reads as evasion.
6. **Do not promise anything** the control tower has not committed to. No compensation,
   no guaranteed recovery, no "we will expedite" unless the evidence says so.
7. Four sentences at most. Plain text, no markdown, no subject line, no signature block
   — the sending layer adds those.

## Worked judgement calls

- Predicted 899 minutes against a planned 388, severity `high`, corridor is a
  statistically confirmed bottleneck → lead with roughly eight and a half hours late,
  name the corridor, note that this route consistently runs over plan, stop.
- Predicted 61 minutes against a planned 46, severity `low`, no corridor evidence →
  one sentence that it is running about fifteen minutes late, one that the team is
  tracking it. Nothing else: a low-severity delay does not need four sentences.
- Evidence lists a cold-start corridor (no history) → say the estimate is based on
  limited history for this route. Do not present it with the same confidence as a
  prediction backed by hundreds of legs.
